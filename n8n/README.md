# n8n workflows for Circle

Importable workflows (n8n → Workflows → Import from file). They send WhatsApp messages through
the **WhatsApp Cloud API**. WhatsApp only allows free-form text inside the 24-hour window after
the person's last message, so reminders, confirmations and the weekly report use **approved
message templates**; replies of the AI assistant and the front desk are free text (they always
answer a patient who just wrote).

| File | What it does |
| --- | --- |
| `booking-confirmation.workflow.json` | Receives Circle's `appointment.booked` webhook and sends the patient a confirmation with their self-service link. |
| `reminders.workflow.json` | Every 30 minutes asks Circle for due reminders (`GET /api/v1/reminders`), sends each one, then marks it sent. |
| `whatsapp-agent.workflow.json` | Meta webhook for the clinic numbers: verifies Meta's signature, hands each patient message to Circle's AI assistant and sends its reply. |
| `whatsapp-send.workflow.json` | Internal webhook Circle uses to send a free-text message (front-desk replies from the **المحادثات** inbox). |
| `weekly-report.workflow.json` | Every Sunday 7:00 sends the clinic owner a summary of the past week (`GET /api/v1/reports?days=7`) — numbers only. |

## Setup

1. **Environment** (set by `deploy/docker-compose.circle.yml`): the workflows read `$env.CIRCLE_URL`
   (the app on the internal network, `http://app:3000`) and `$env.WHATSAPP_PHONE_NUMBER_ID`
   (set `WHATSAPP_PHONE_NUMBER_ID` in `/opt/circle/supabase/.env`, then `deploy/deploy.sh`).
   A clinic with its own WhatsApp number: in its copy of the workflow, replace
   `{{ $env.WHATSAPP_PHONE_NUMBER_ID }}` with that clinic's phone number id.
2. **Credentials** (all *Header Auth*):
   - *Circle clinic key*: `Authorization` = `Bearer ck_…` — create the key in Circle → **الأتمتة**. One key = one clinic.
   - *WhatsApp Cloud API*: `Authorization` = `Bearer <permanent access token>`.
   - *Circle webhook secret*: `x-circle-secret` = the value of `N8N_WEBHOOK_SECRET` in `/opt/circle/supabase/.env` (generated by `install.sh`).
3. In `/opt/circle/supabase/.env` set `N8N_BOOKING_WEBHOOK_URL` to the “Booking from Circle” node's
   production path on the internal network — `http://n8n:5678/webhook/<path>` — then run `deploy/deploy.sh`.
4. In Circle → **الأتمتة**, tick “إرسال تذكير واتساب قبل الموعد” and choose how many hours before.
5. Submit the two templates below in Meta Business Manager (category **Utility**, language **ar**)
   and wait for approval before activating the workflows.

## Several clinics

Each clinic has its own Circle key. Duplicate `reminders.workflow.json` per clinic and give each
copy that clinic's credential (the WhatsApp credential can be shared if you send from one number).

## WhatsApp AI assistant (built in)

Circle has its own assistant (Claude, by Anthropic) that answers patients on the clinic's WhatsApp
number: it books, reschedules, cancels and confirms from real open times, answers from the clinic
data and its **knowledge base**, and hands complaints, medical questions and anything unclear to
the front desk, who continue the chat from **المحادثات** in the dashboard.

How a message flows:

```
Patient ─WhatsApp─▶ Meta ─webhook─▶ n8n "WhatsApp agent" (checks X-Hub-Signature-256)
   ─▶ POST {CIRCLE_URL}/api/whatsapp/inbound (x-circle-secret)
        Circle: route by phone_number_id → store message → assistant (tools scoped to this
        clinic + this phone) → reply stored
   ◀─ { reply } ─ n8n sends it with the Graph API ─▶ Patient
Front desk reply (dashboard) ─▶ Circle ─▶ n8n "circle-send" webhook ─▶ Meta ─▶ Patient
```

Setup:

1. **Anthropic key**: put `ANTHROPIC_API_KEY` in `/opt/circle/supabase/.env` (optional:
   `AGENT_MODEL`, default `claude-opus-5`; a cheaper choice is `claude-sonnet-5`), then `deploy/deploy.sh`.
2. **Meta app** (developers.facebook.com → WhatsApp): note the app secret and the clinic number's
   *phone number id*. Put `WHATSAPP_APP_SECRET` in `.env` (`WHATSAPP_VERIFY_TOKEN` is generated by `install.sh`).
3. Import `whatsapp-agent.workflow.json` and `whatsapp-send.workflow.json`, attach the *WhatsApp
   Cloud API* and *Circle webhook secret* credentials, and activate both.
4. In Meta → WhatsApp → Configuration → Webhook: callback URL = the production URL of the
   “Meta webhook” node (`https://n8n.<your domain>/webhook/whatsapp`), verify token =
   `WHATSAPP_VERIFY_TOKEN`; subscribe to **messages**.
5. In Circle (as Circle staff) → the clinic → **الأتمتة** → *المساعد الذكي على واتساب*: enter the
   phone number id, add knowledge entries (insurance, parking, offers…), and turn the assistant on.
   Only Circle staff can link a number, so no clinic can receive another clinic's messages.

Privacy: patient messages are sent to Anthropic to generate replies (disclose this in the clinic's
privacy notice); conversations are deleted after 90 days. The assistant never gives medical advice
and sends emergencies to 997.

## Reports

`GET /api/v1/reports?days=7` (1–92 days) returns the clinic's summary: visits by status, doctor,
service, source and day, no-show and cancellation rates, estimated revenue, new patients and
WhatsApp activity — counts only — plus a ready Arabic `message` and the `template_params` for
`weekly_report`. In `weekly-report.workflow.json` set the owner's number in the **Settings** node.
Managers see the same numbers live in **التقارير** and can download the period as CSV.

## Your own AI agent (API)

The same key lets an AI agent (n8n AI Agent node, or any tool-calling LLM) work for the clinic:

| Tool | Call |
| --- | --- |
| Clinic facts (RAG context) | `GET /api/v1/clinic` |
| Open times | `GET /api/v1/slots?service=…&day=YYYY-MM-DD[&doctor=…]` |
| Book | `POST /api/v1/appointments` `{ service_id, doctor_id, branch_id, starts_at, full_name, phone, source: "whatsapp" }` |
| Patient's bookings | `GET /api/v1/appointments?phone=05…` |
| Reschedule | `POST /api/v1/appointments/{id}/reschedule` `{ phone, starts_at }` |
| Cancel | `POST /api/v1/appointments/{id}/cancel` `{ phone }` |

Reschedule/cancel require the patient's phone to match the appointment, so the agent can only act
for the person it is chatting with. Changes respect the clinic's cutoff (“too_late_to_change”).
